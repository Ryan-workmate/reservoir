# 校园活动管理系统 V1.0 — 需求分析

## 1.1 业务问题与用户目标

### 业务问题

校园活动目前靠群通知、海报等方式发布，信息分散；学生不知道有哪些活动可以参加、怎么报名；教师发布活动后难以统计报名人数和名单，管理效率低。

### 用户角色与目标

| 角色 | 核心目标 |
|---|---|
| 学生 | 快速了解校园有哪些活动，方便地报名参加，随时查看自己报了哪些活动 |
| 活动组织教师 | 方便地发布活动信息，查看活动报名情况和名单，对活动进行基本管理 |

## 1.2 用户故事

### 学生角色

| 编号 | 用户故事 | 对应需求 |
|---|---|---|
| US-01 | 作为一个学生，我希望注册账号，以便能登录系统参与校园活动 | REQ-01 |
| US-02 | 作为一个学生，我希望用用户名和密码登录，以便进入系统查看和报名活动 | REQ-02 |
| US-03 | 作为一个学生，我希望浏览所有活动列表和详情，以便了解有哪些活动可以参加、活动时间地点在哪 | REQ-03 |
| US-04 | 作为一个学生，我希望报名参加感兴趣的活动，以便获得参与资格，同时系统能防止我重复报名或报名已满的活动 | REQ-04 |
| US-05 | 作为一个学生，我希望取消已报名的活动，以便时间冲突时能退出并把名额让给其他同学 | REQ-05 |
| US-06 | 作为一个学生，我希望查看自己的报名记录，以便随时知道自己报了哪些活动、活动状态如何 | REQ-06 |

### 教师角色

| 编号 | 用户故事 | 对应需求 |
|---|---|---|
| US-07 | 作为一个活动组织教师，我希望注册账号，以便能登录系统发布和管理活动 | REQ-01 |
| US-08 | 作为一个活动组织教师，我希望登录系统，以便进入管理界面处理我的活动 | REQ-02 |
| US-09 | 作为一个活动组织教师，我希望发布活动（填写标题、描述、时间、地点、名额），以便让学生看到并报名参加 | REQ-07 |
| US-10 | 作为一个活动组织教师，我希望查看我发布的活动列表和每个活动的报名名单，以便了解报名情况和参与学生信息 | REQ-08 |
| US-11 | 作为一个活动组织教师，我希望取消已发布的活动，以便活动无法举办时及时停止报名并告知已报名学生 | REQ-09 |

## 1.3 V1.0 需求清单

| 需求编号 | 用户/角色 | 需求描述 | 优先级 | 验收依据 |
|---|---|---|---|---|
| REQ-01 | 学生/教师 | 用户可以注册账号，注册时选择角色（学生或教师），用户名不能重复 | 高 | 注册成功后可登录；重复用户名注册被拒绝 |
| REQ-02 | 学生/教师 | 已注册用户可以通过用户名+密码登录，登录后进入对应角色的首页 | 高 | 正确账号密码登录成功；错误密码提示失败；未登录不能访问需登录的页面 |
| REQ-03 | 学生 | 学生可以浏览所有活动列表，查看活动详情（标题、描述、时间、地点、剩余名额、状态） | 高 | 活动列表展示所有活动；点击可查看详情；名额和状态显示正确 |
| REQ-04 | 学生 | 学生可以报名参加"报名中"且有名额的活动；不能重复报名同一活动；名额满了不能报名 | 高 | 正常报名成功；重复报名被拒绝；名额满时报名被拒绝；报名后剩余名额减1 |
| REQ-05 | 学生 | 学生可以取消自己已报名的活动，取消后名额释放 | 中 | 取消后报名记录消失；该活动名额加1 |
| REQ-06 | 学生 | 学生可以查看自己已报名的活动列表 | 中 | 列表显示当前用户报名的所有活动及状态 |
| REQ-07 | 教师 | 教师可以发布活动，填写标题、描述、开始时间、地点、最大报名人数 | 高 | 发布后活动出现在活动列表中；字段保存正确 |
| REQ-08 | 教师 | 教师可以查看自己发布的活动列表，以及每个活动的报名学生名单 | 高 | 列表显示本人发布的活动；点击可查看报名学生名单 |
| REQ-09 | 教师 | 教师可以取消自己发布的活动；活动取消后学生不能再报名，已报名学生的记录标记为活动已取消 | 中 | 取消后活动状态变为"已取消"；学生端该活动不能报名；报名名单中显示活动已取消 |

## 1.4 需求取舍与范围控制（明确不做的）

1. **不做活动审核流程** — 教师发布活动即上线，不需要管理员审核。V1.0假设教师都是可信的，减少一个角色和一套审批流程。
2. **不做消息通知** — 不做站内信、邮件或短信提醒。活动状态变化、报名成功都靠用户自己登录查看，降低复杂度。
3. **不做活动评价/反馈** — 活动结束后不做评分、评论、反馈收集。V1.0只覆盖"发布→报名→参与"的前半段。
4. **不做管理员角色** — 只有学生和教师两种角色，不做后台管理、用户管理、数据统计报表。
5. **不做数据导出** — 教师查看报名名单即可，不提供导出 Excel/PDF 功能。

---

## 1.5 需求总结

以上 9 条需求、11 条用户故事形成一个完整闭环：

**注册 → 登录 → 教师发布活动 → 学生浏览活动 → 学生报名/取消 → 教师查看报名名单 → 教师取消活动**
