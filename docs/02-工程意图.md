# 校园活动管理系统 V1.0 — 工程意图

| 维度 | 内容 |
|---|---|
| **建设目的** | 解决校园活动信息分散、报名统计靠人工的问题，为学生提供统一的活动浏览和报名入口，为教师提供活动发布和报名管理工具，用一个最小可用版本验证核心业务流程能否跑通。 |
| **本轮范围** | **做：** 用户注册登录（学生/教师两种角色）、活动发布、活动浏览与详情、活动报名与取消、报名记录查看、报名名单查看、活动取消。**不做：** 活动审核、消息通知、活动评价、管理员后台、数据导出。 |
| **重要约束** | ① 技术约束：Python + Flask + SQLite，单文件后端，不依赖外部数据库服务；② 数据约束：用户名唯一，报名不能重复，报名数不能超过活动名额上限；③ 安全约束：密码不能明文存储，未登录用户不能访问需登录的页面，用户只能操作自己的数据（学生只能取消自己的报名，教师只能管理自己发布的活动）；④ 运行约束：一条命令启动，浏览器直接访问，不需要额外配置。 |
| **完成依据** | ① 9条需求（REQ-01 ~ REQ-09）全部实现并可运行；② 核心业务流程"教师发活动→学生报名→教师看名单"能完整走通；③ 报名规则（重复报名、名额满、活动取消后不能报名）全部正确生效；④ 未登录访问受保护页面会被拦截；⑤ 项目能通过 `python app.py` 一键启动并正常使用。 |
| **与需求关系** | 对应 REQ-01 ~ REQ-09 全部需求，覆盖 US-01 ~ US-11 全部用户故事。 |
