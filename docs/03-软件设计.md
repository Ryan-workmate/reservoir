# 校园活动管理系统 V1.0 — 软件设计

## 3.1 总体设计

**技术架构：** 经典的服务端渲染（SSR）三层结构，不做前后端分离。

```
┌─────────────────────────────────┐
│         浏览器（前端）            │
│  Jinja2模板 + CSS + 少量JS       │
└──────────────┬──────────────────┘
               │ HTTP请求/响应
┌──────────────▼──────────────────┐
│         Flask（后端）             │
│  路由层 → 业务逻辑层 → 数据访问层  │
└──────────────┬──────────────────┘
               │ SQL
┌──────────────▼──────────────────┐
│        SQLite（数据库）           │
│   users / activities / registrations │
└─────────────────────────────────┘
```

**模块划分（单文件 app.py，按功能分段）：**

| 模块 | 职责 | 对应需求 |
|---|---|---|
| auth（认证） | 注册、登录、登出、登录状态检查 | REQ-01, REQ-02 |
| activity（活动） | 活动列表、详情、发布、取消 | REQ-03, REQ-07, REQ-09 |
| registration（报名） | 报名、取消报名、我的报名、报名名单 | REQ-04, REQ-05, REQ-06, REQ-08 |

**页面清单：**

| 页面 | 访问者 | 功能 |
|---|---|---|
| 登录页 / 注册页 | 未登录用户 | 账号注册、登录 |
| 活动列表页 | 所有登录用户 | 浏览所有活动，按状态筛选 |
| 活动详情页 | 所有登录用户 | 查看活动详情，学生可报名/取消 |
| 我的报名页 | 学生 | 查看自己报名的活动列表 |
| 发布活动页 | 教师 | 填写活动信息并发布 |
| 我的活动页 | 教师 | 查看自己发布的活动列表 |
| 活动管理页 | 教师 | 查看单个活动的报名名单，取消活动 |

## 3.2 核心业务流程

### 流程一：学生查看活动并报名

```
学生登录 → 进入活动列表页 → 点击某个活动查看详情
    → 点击"报名" → 系统校验：
        ├─ 活动状态是否为"报名中"？→ 否，提示"活动已取消，无法报名"
        ├─ 是否已报名该活动？→ 是，提示"您已报名该活动"
        └─ 剩余名额是否 > 0？→ 否，提示"报名名额已满"
    → 全部通过 → 创建报名记录，活动已报名数+1 → 提示"报名成功"
    → 学生可在"我的报名"中看到该活动
```

### 流程二：教师发布活动并查看报名名单

```
教师登录 → 点击"发布活动" → 填写标题/描述/时间/地点/名额 → 提交
    → 系统校验字段非空、名额为正整数 → 创建活动（状态：报名中）
    → 跳转到"我的活动"列表，可看到新发布的活动
    → 点击活动 → 进入活动管理页 → 查看报名学生名单
    → 如需取消 → 点击"取消活动" → 确认后活动状态变为"已取消"
        → 学生端该活动显示"已取消"，不能再报名
```

## 3.3 数据设计

### users（用户表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | 用户ID |
| username | TEXT | NOT NULL, UNIQUE | 用户名，登录用 |
| password_hash | TEXT | NOT NULL | 密码哈希（不存明文） |
| role | TEXT | NOT NULL, CHECK(role IN ('student','teacher')) | 角色：学生/教师 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 注册时间 |

### activities（活动表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | 活动ID |
| teacher_id | INTEGER | NOT NULL, FOREIGN KEY → users.id | 发布教师ID |
| title | TEXT | NOT NULL | 活动标题 |
| description | TEXT | NOT NULL | 活动描述 |
| location | TEXT | NOT NULL | 活动地点 |
| start_time | DATETIME | NOT NULL | 活动开始时间 |
| max_participants | INTEGER | NOT NULL, CHECK(max_participants > 0) | 最大报名人数 |
| status | TEXT | NOT NULL, DEFAULT 'open', CHECK(status IN ('open','cancelled')) | 状态：报名中/已取消 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 发布时间 |

### registrations（报名表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | 报名记录ID |
| user_id | INTEGER | NOT NULL, FOREIGN KEY → users.id | 报名学生ID |
| activity_id | INTEGER | NOT NULL, FOREIGN KEY → activities.id | 活动ID |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 报名时间 |

**约束：** `(user_id, activity_id)` 联合唯一，防止重复报名。

**表关系：**
- users 1──N activities（一个教师发布多个活动）
- users 1──N registrations（一个学生报名多个活动）
- activities 1──N registrations（一个活动有多个报名）

## 3.4 关键设计决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D-01 | 密码用 werkzeug 的 generate_password_hash 哈希存储，登录时用 check_password_hash 校验 | 满足安全约束，不存明文密码；Flask 自带，不需要额外依赖 |
| D-02 | 用 Flask session 管理登录状态，session 中存 user_id 和 role | 轻量，服务端渲染场景下最直接；配合装饰器做登录和角色校验 |
| D-03 | 活动状态只设"报名中(open)"和"已取消(cancelled)"两种，不设"已结束" | V1.0不做活动自动结束逻辑，简化状态机；活动时间只做展示，不做自动状态切换 |
| D-04 | 取消报名 = 直接删除 registrations 记录，不保留取消状态 | V1.0不需要报名历史审计，删除最简单直接；删除后名额自动释放（名额通过 COUNT 报名记录实时计算，不存冗余字段） |
| D-05 | 活动已报名人数不存冗余字段，通过 COUNT(registrations) 实时查询 | 避免数据不一致；V1.0数据量小，实时查询性能足够 |
| D-06 | 权限控制用两个装饰器：@login_required（检查登录）和 @teacher_required（检查教师角色） | 统一拦截，避免每个路由重复写校验逻辑；学生操作（报名/取消）在业务逻辑里额外校验"只能操作自己的" |
